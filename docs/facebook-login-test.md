# Facebook developer login test

Run `npm run facebook:login` (on Windows PowerShell, use `npm.cmd run facebook:login` if script execution is disabled). Open <http://localhost:8002/v1/facebook/login-test>. This standalone server needs no database or Redis. The main API also serves the page at `/v1/facebook/login-test` on its own port.

Set these values in `.env`, using your own Meta app credentials:

```dotenv
FACEBOOK_APP_ID=your_numeric_app_id
FACEBOOK_APP_SECRET=your_app_secret
FACEBOOK_GRAPH_VERSION=vXX.0
FACEBOOK_TEST_LOGIN_MODE=classic
```

Replace `vXX.0` with an active Graph API version supported by your app dashboard. Restart the server after changing the environment. The page reports missing configuration; credentials cannot be generated by this project.

In [Meta for Developers](https://developers.facebook.com/apps/), enable the Facebook Login product/use case available to your app. Add your account as an administrator, developer or tester and accept the invitation. In the login settings, enable web OAuth login and register the **exact callback shown on the test page**. With the default standalone server this is:

```text
http://localhost:8002/v1/facebook/login-test/callback
```

For a public HTTPS development tunnel, set `FACEBOOK_TEST_PUBLIC_URL=https://your-tunnel-host`, forward it to port 8002 and register `https://your-tunnel-host/v1/facebook/login-test/callback`. Open the page on that same origin. If your app disallows HTTP localhost, use the HTTPS tunnel. `FACEBOOK_TEST_PORT` changes the standalone port. The standalone listener binds to loopback.

The test origin defaults to `FACEBOOK_TEST_PUBLIC_URL`, then `FACEBOOK_PUBLIC_URL`, then the local server URL. If your Messenger origin is already configured, set `FACEBOOK_TEST_PUBLIC_URL` explicitly to the origin used for this test.

Click **Continue with Facebook**. Facebook hosts the actual login and consent screen. The page shows your app-scoped ID, name and permission statuses. The default classic flow requests only `public_profile`. If your app only supports Facebook Login for Business, set `FACEBOOK_TEST_LOGIN_MODE=business` and `FACEBOOK_LOGIN_CONFIG_ID` to the configuration ID from your app, using a configuration that issues a **user** access token. The business flow requests the permissions in that configuration.

The server exchanges the authorization code and checks `/me` and `/me/permissions`. Access tokens are never sent to the page or saved. A signed, HttpOnly cookie contains only the profile and permission results, expires after ten minutes, and can be cleared with **Clear test session**. This does not log you out of Facebook or revoke permissions. Pending OAuth attempts are held in memory, bound to a browser cookie, expire after ten minutes and can be used only once; a server restart requires starting login again. Use a single server process for this test.

These routes are disabled when `NODE_ENV=production`. The test does not create a SaaS account, issue a company JWT, connect a Page or subscribe to Messenger. Use the existing `/v1/facebook/page` for Messenger testing.

If login fails, check the app credentials, active API version, selected login product, exact redirect URI and accepted app role. A declined login or expired attempt can be retried from the page.

References: [Meta manual login flow](https://developers.facebook.com/docs/facebook-login/manually-build-a-login-flow/) and [Firebase's official Facebook integration guide](https://firebase.google.com/docs/auth/web/facebook-login), which covers app credentials, redirect registration and localhost development mode. Meta's documentation returned access/rate-limit errors during this implementation; the private app settings and a real Facebook login still need verification by the app owner.
