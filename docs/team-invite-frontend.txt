Team invitation: email or shareable link

Endpoint: POST /v1/admin/team/invite
Authorization: Bearer <existing-dashboard-JWT>

Keep the existing invite form and add a delivery selector:
- Send email (default): delivery_method = "email"
- Generate link: delivery_method = "link"

Example request:
{
  "name": "New Teammate",
  "email": "teammate@example.com",
  "phone_number": "919876543210",
  "role": "member",
  "permission": ["inbox", "contact"],
  "domain_name": "app.whatsgo.in",
  "delivery_method": "link"
}

domain_name selects the hostname used in the generated link. It does not need
a company_domains record. Pass a hostname only, without https://, paths, query
parameters or a port. For example, "acer.soft7.in" returns:
https://acer.soft7.in/team/setup-password?token=<generated-token>
The backend normalizes casing and surrounding whitespace and saves the hostname
on the invitation. The API hostname (including ngrok) does not override it.
The hostname must serve your frontend setup-password page with valid HTTPS for
the link to open. Generating a link does not configure DNS, hosting, or login
domain registration; existing login-domain checks still apply after acceptance.
Do not pass a company ID, owner ID or plan ID: those come from authentication.
Email, phone number, role and domain_name remain required in both modes.

Successful response (existing invitation fields are preserved):
{
  "success": true,
  "message": "Team invite link generated successfully",
  "data": {
    "id": "<invite-id>",
    "email": "teammate@example.com",
    "invite_status": "sent",
    "invite_url": "https://app.whatsgo.in/team/setup-password?token=<generated-token>",
    "delivery_method": "link",
    "email_sent": false
  }
}

In link mode, show a read-only input containing response.data.invite_url and a
Copy link button. For Axios, the path is response.data.data.invite_url. The user
can copy/share the link with the named recipient. The backend sends no email
in this mode. Do not automatically call the invite endpoint again when copying.

In email mode (or when delivery_method is omitted), the backend keeps sending
the existing invitation email. The response also includes invite_url,
delivery_method: "email", and email_sent: true only after sending succeeds.
An email delivery failure still removes the pending invitation and releases
its reserved seat; the user can then retry using Generate link.

Disable submission while creating the invitation. Show returned validation,
duplicate-invite and plan-limit errors. Both modes reserve a team seat. The
legacy database status "sent" means pending, including for link-only invites;
use email_sent for the creation confirmation instead of claiming an email was
sent in link mode. Delivery mode is response metadata, not a new database field.
The invite-list endpoint's response is unchanged.

The existing setup-password page accepts the link's token and submits:
POST /v1/auth/setup-password
{ "token": "<token-from-link>", "password": "<new-password>",
  "domain_name": "app.whatsgo.in" }
Use the same hostname saved in the invite for this password-setup request.
Keep the existing password requirements. The invite is bound to its saved
hostname, email, role, permissions and company; it can be accepted only once.
The company comes from the invitation, never from the submitted hostname.
Legacy invitations without a saved hostname retain the company-domain check. Existing
invitations are not regenerated by this endpoint. Existing deletion revokes a
pending link. No new automatic expiry has been added; do not show an expiry
countdown. Treat invite_url as a secret: do not log it or send it to analytics.

No database migration is required. Deploy the backend change before enabling
Generate link in the frontend; an older backend ignores the new delivery field
and will still send email.
